# Build gitignored Grimmory book database in AmazonWishlist

Task: We are going to make changes to the Amazon wishlist repo. We will make these changes in steps. Step 1 - 
1. The home lab has a Grimmory instance at "http://192.168.1.13:6060/". Username - fksogbetun Password Synergy&1
2. The Grimmory instance has multiple libraries including - A) "Amazon fksogbetun" B) "Amazon rivaborn"
3. We will create a database that includes a list of all the books in both libraries. 
4. We will save the Name, Author, Publisher, Date Published and ISBN when available
5. This database will be added to the Amazon Wishlist repository and gitignored

Also add an explicit `data/grimmory.db` entry to .gitignore (data/ already ignores it, this is explicit/unambiguous). Assumption: the build DB is a standalone file data/grimmory.db, separate from the app's wishlist.db, since this is a one-off catalog export with its own schema.

- [ ] Step 2: Add app/grimmory.py — a small httpx client module (httpx is already a dependency) wrapping the Grimmory/BookLore v1 JSON API confirmed from source: `login(username,password)->str` POSTs /api/v1/auth/login and returns the Bearer accessToken; `list_libraries(token)->list[dict]` GETs /api/v1/libraries; `fetch_library_books(token,library_id)->list[dict]` GETs /api/v1/libraries/{id}/book; and `books_to_rows(books, library_id, library_name)->list[dict]` maps each Book JSON to {title, author (','.join(metadata.authors)), publisher (metadata.publisher), published_date (metadata.publishedDate ISO), isbn (metadata.isbn13 else metadata.isbn10), library_id, library_name}, tolerating null metadata. Add a `__main__` probe that logs in, lists all libraries, prints each with its book count, and exits non-zero if any of the target GRIMMORY_LIBRARIES names are missing. No password is written to any committed file; it is read from env at runtime.

- [ ] Step 3: Add scripts/build_grimmory_db.py — a runnable one-off that logs in to Grimmory, resolves the target GRIMMORY_LIBRARIES to their library IDs from /api/v1/libraries, fetches every book via /api/v1/libraries/{id}/book for each, and writes data/grimmory.db (sqlite3 stdlib) with a `book` table (library_id, library_name, title, author, publisher, published_date, isbn). It DROPs+recreates the table each run so it always reflects current data, and fails loudly (non-zero exit, clear message) if a target library is absent, login fails, or an HTTP call errors. This is the operational step that actually creates the gitignored database required by the task.
