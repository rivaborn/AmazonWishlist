# Deduplicate deals.db (keep most recent book deals)

Task: The next step is deduplication. 
1. Make a copy of the database
2. Go through the database and check if any deals are repeats i.e. the same book more than once
3. For any repeats, keep the most recent deal and remove the others

- [ ] Step 1: Add a `deduplicate(conn) -> int` function to app/deals_db.py that removes repeated books keeping the most recent deal. Identity of 'the same book': the Amazon ASIN extracted from `amazon_url` (regex `/dp/([A-Z0-9]{10})`, ignoring the `?_bbid=...&tag=...` tracking suffix); rows with no Amazon link (`no_amazon_link=1`, `amazon_url` NULL) fall back to the existing `normalise(title)`, `normalise(author)` pair. The function reads all (id, date, title, author, amazon_url), groups rows by that identity, and for every group of size >1 keeps the single row with the largest `date` (YYYYMMDD, lexicographic = chronological); a tie (same date) keeps the highest `id` (most recent insert). It then DELETEs the non-kept duplicate rows and returns the number removed. It never updates the retained row (no merging; the kept row keeps its own columns/date) and never touches unique rows. ASSUMPTIONS (recorded): ASIN is the canonical same-book key (a book re-featured on different dates shares its ASIN); 'most recent deal' = the newest `date`, tie-broken by highest `id`; dedup only removes (it never edits), so idempotent — a second call removes 0.
  - files: app/deals_db.py
  - verification: From repo root: `python -m py_compile app/deals_db.py`, then a `python - <<'PY'` that creates a temp deals.db (ensure_schema), inserts rows with a known mix — (a) same ASIN on 2 dates (expect the newer date kept), (b) same ASIN on 3 dates incl. a same-date pair with two bookbub_urls (expect newest date kept, tie -> higher id), (c) a no-amazon book (amazon_url NULL, no_amazon_link=1) duplicated by normalised title+author on 2 dates (expect newer kept), (d) a unique book (expect untouched) — then runs deduplicate(conn) and asserts: returned count equals the number of duplicate rows removed, afterwards every (asin-or-meta) identity appears exactly once, the kept row's date equals the max date of its original group, and running deduplicate again returns 0 (idempotent). Prints `ok`.
